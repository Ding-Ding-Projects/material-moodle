    Deploy

    Run the Docker stack on any machine, put it online with a Cloudflare tunnel, or let the desktop deployer do it over SSH.

    Run with Docker

    One command installs and starts everything. Run it on the server as a user who can use Docker or sudo.

    bash <(curl -fsSL https://raw.githubusercontent.com/Ding-Ding-Projects/material-moodle/main/material/install.sh)
    1. Answer a few questionsA terminal menu asks for the site name, administrator and how people reach the site. Press Enter to accept each suggestion.
    2. Passwords are made for youThe installer generates the database and administrator passwords and writes the .env file. Docker is installed first if it is missing, after you agree.
    3. Moodle startsThe first start installs Moodle and applies the Material defaults. The installer waits until the site answers.
    4. Open your linkThe installer prints the address and the administrator sign-in. The setup wizard opens when you first sign in.

    Change your answers

    Run the same command again to restart with your saved answers, or add --reconfigure to change them.

    bash <(curl -fsSL https://raw.githubusercontent.com/Ding-Ding-Projects/material-moodle/main/material/install.sh) --reconfigure

    Automation

    Add --yes to skip the menu and set the answers with MM_ variables. Anything you leave out uses the suggestion, and passwords are still generated.

    MM_SITE_NAME="Our School" MM_ADMIN_EMAIL=admin@example.org MM_ACCESS=quick \
  bash <(curl -fsSL https://raw.githubusercontent.com/Ding-Ding-Projects/material-moodle/main/material/install.sh) --yes
    VariableMeaning
    MM_DIRFolder for the stack (default ~/material-moodle)
    MM_SITE_NAME, MM_SHORT_NAMESite name and short name
    MM_ADMIN_USER, MM_ADMIN_EMAIL, MM_ADMIN_PASSWORDFirst administrator (the password is generated if empty)
    MM_PORTPort on the server
    MM_ACCESSlocal, quick (Cloudflare quick link), token (named tunnel) or url (your own address)
    MM_TUNNEL_TOKEN, MM_PUBLIC_URLTunnel token and public address
    MM_SEED_COLOR, MM_PASSKEYSSeed colour, and 1 or 0 for passkey sign-in
    MM_IMAGEContainer image to use

    Manual setup from a checkout

    Prefer to do it by hand? The installer also works from a clone of the repository, using its Compose file.

    git clone https://github.com/Ding-Ding-Projects/material-moodle
bash material-moodle/material/install.sh

    Put it online

    Quick link

    No account. You get a random address that changes when the tunnel restarts. Choose it in the installer menu.

    Your own domain

    A permanent address on a domain in your Cloudflare account. Paste a tunnel token from the dashboard into the installer.

    The installer sets these up for you. To switch an existing stack by hand, from the stack folder:

    # Quick link (temporary trycloudflare.com address)
docker compose --profile quicktunnel up -d
docker compose logs quicktunnel | grep -o 'https://[a-z0-9-]*\.trycloudflare\.com'
    # Your own domain: put these in .env, then start the tunnel profile
CLOUDFLARE_TUNNEL_TOKEN=<token from the Cloudflare dashboard>
MOODLE_WWWROOT=https://moodle.example.org
docker compose --profile tunnel up -d

    Read the Cloudflare tunnel article

    Environment variables

    The installer writes these to .env for you. They are listed here for reference.

    VariableDefaultMeaning
    MOODLE_ADMIN_PASSWORDnoneFirst administrator password, required at first start
    MOODLE_DB_PASSWORDnoneDatabase password, required
    MOODLE_SITE_NAMEMaterial MoodleSite name at first install
    MOODLE_ADMIN_USERadminFirst administrator user name
    MOODLE_WWWROOThttp://localhost:8080Public address, or auto for quick tunnels
    MOODLE_TRUSTED_HOSTSlocalhost, *.trycloudflare.comHost names accepted when the address is auto
    MOODLE_PORT8080Port on the host
    MATERIAL_SEED_COLOR#8B5000Seed colour applied at first start
    MATERIAL_ENABLE_PASSKEYS1Enable passkey sign-in at first start
    CLOUDFLARE_TUNNEL_TOKENemptyToken for the named tunnel profile

    Updating

    Back up both volumes, then pull the new image from the stack folder. Moodle's upgrade runs when the container starts.

    cd ~/material-moodle
docker compose pull
docker compose up -d

    Desktop deployer

    Material Moodle Deployer will deploy the stack to any Linux server you can reach over SSH, install Docker if it is missing, and set up a Cloudflare tunnel with a guided sign-in. It is still being built, so there is no installer yet.
