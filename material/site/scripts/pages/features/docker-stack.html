Docker stack

PostgreSQL, Moodle and cron containers that install Moodle and apply the Material defaults on first start.

First start

The entrypoint waits for PostgreSQL, installs Moodle with the site name and administrator from .env, then selects the Material theme, turns on colour modes, applies MATERIAL_SEED_COLOR and enables passkey sign-in. The log prints MATERIAL_MOODLE_INSTALLED when it is done, and the first administrator to sign in is taken to the setup wizard. Later starts run Moodle's upgrade and keep settings you changed.

The one-command installer asks a few questions, generates the passwords and .env, starts the stack, waits until Moodle answers and prints the link:

bash <(curl -fsSL https://raw.githubusercontent.com/Ding-Ding-Projects/material-moodle/main/material/install.sh)

Run it again with --reconfigure to change your answers, or with --yes and MM_ variables for automation.

The Deploy page lists every command and the environment variables.

Security

  • .env holds the generated passwords and the tunnel token; keep it private and out of version control.
  • PostgreSQL is not published on a host port.
  • The installer generates strong passwords; if you write .env by hand, never keep the example values.
