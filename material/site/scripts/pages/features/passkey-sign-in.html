Passkey sign-in

Sign in with a fingerprint, face, screen lock or security key. Passwords keep working.

Availableauth_passkey

What it does

The plugin adds a sign-in route to accounts of any authentication method; it never owns accounts, so a manual account keeps its password as a fallback. The sign-in page shows a large Sign in with a passkey button. Browsers without WebAuthn support do not get the button.

How a sign-in works

  1. The browser asks the site for options. The server creates a single-use challenge and keeps it in the session.
  2. The device offers a passkey for this site. Nobody types a username.
  3. The server verifies the signature, origin, challenge and user verification with the bundled lbuchs/webauthn library.
  4. The account must be active and its authentication method enabled. Moodle's normal sign-in then runs.

Security

  • Only the public key, credential id, signature counter, authenticator model, name and dates are stored. Biometric data never leaves the device.
  • The user handle sent to devices is a hash, not the Moodle user id.
  • Every action needs Moodle's session key; challenges are single-use.
Passkeys belong to one host name. Use a fixed address (a named tunnel or your own domain) before people add passkeys; a quick tunnel address changes on every restart.
